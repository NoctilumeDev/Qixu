## 每阶段的施工要求

正式开始前在施工记录写范围、保护行为、不做内容、验收与停止条件；当前阶段的架构/API细节进入相应文档。每个有独立问题的修改使用单一目的提交/分支，重要阶段有稳定引用。

每个正常业务链至少观察：前端请求 → 权限 → 后端事务 → MySQL最终事实 → 返回结果 → 页面状态。页面正常不替代权限/并发证据；自动测试正常不替代真实页面和微信设备行为。

每阶段的验迹 Plan 必须在对应执行前封存，明确 exact subject、采集器合同、必需证据、停止条件和适用边界。实际进入 Core 的证据由执行采集器生成，保留失败/缺证据/污染，不根据预期倒填事实。验迹接入方式及各层责任见 [verification.md](verification.md)。

遇到失败先判断产品、验证器、工具污染、宿主条件、公开治理或声明漂移，再修对应边界；不为测试绿灯删掉正确拒绝条件。
