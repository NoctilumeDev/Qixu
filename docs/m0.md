# M0 · 知道要建什么

状态：需求基线候选；2026-10-03。用户已授权按完整流程完成项目，未来里程碑的完成需要真实证据。

## 问题与身份

期序（Qixu）是独立的校园空间预约与使用权管理系统。有限的短期流动资源、长期备考席位和用途不同的场地，需要不同分配机制，同时维护一套一致的空间冲突事实。

第一阶段服务图书馆所属空间，包含普通自习区、备考区、研讨室、教室和活动场地。其他部门后续通过管理范围和接入合同扩展，不为未来能力预先堆叠基础设施。

暗室藏书、青野、期序是平级领域。身份提供者回答主体是否有效，期序回答主体对空间有哪些权限；活动来源提交场地需求，期序裁决预约与占用。

## 产品原则

1. 空间先被理解，再被选择。
2. 资格决定参与，分配解决稀缺。
3. 使用事实与使用权分离。
4. 治理针对明确问题，不评价人的努力。
5. 管理员权限受负责空间范围约束；公开解释不泄露其他学生身份和敏感材料。

## 分开保存的事实

| 事实 | 回答的问题 |
| --- | --- |
| 身份 | 当前主体是谁，是否有效，来自哪里 |
| 资格 | 能否参与指定批次或申请指定空间 |
| 分配 | 冻结输入在固定规则下得到什么结果 |
| 使用权 | 谁在什么期间获准使用什么空间 |
| 预约 | 某时段的短期空间请求和确认 |
| 到场记录 | 用户是否作过到场/暂离/离开确认，不代表传感器观察 |
| 占用与处置 | 课程、活动、维护为何限制使用，影响如何解决 |
| 反馈与空间事实 | 学生报告什么，管理员确认什么，修复实际完成什么 |

## 第一版功能

### 理解空间

空间档案含位置、容量、尺寸、设施、入口条件、照片/示意、开放规则、可用时段、活动及维护影响。主观描述标明来源和复核时间；未采集信息显示未知。照片为演示素材时明确标注，不假称真实校园测量。

透明条件筛选支持设施、区域和用途；收藏与少量空间对比帮助填写志愿。楼层图提供缩放、列表替代与详情入口，编号和状态由数据呈现。个人必需条件与偏好分开表达，不引入隐性加权。

### 三种分配机制

- 普通短时资源：随用随约，配置开放时间、预约上限及到场宽限；到期未确认可释放该预约，不处罚学习努力。自由使用区不强制数字预约。
- 长期备考资源：申请窗口内资格确认与志愿填写，冻结后统一分配。人数少于座位数也不退回手速选座，不承诺所有人都能匹配到自己接受的座位。
- 教室/研讨室/活动场地：时间、人数、用途和设施要求申请；依据空间权限审批，最终确认前检查冲突。

### 解释与治理

展示本人分配依据、候补状态、申请与通知。明确退出、周期结束、资格纠正及违规处置的理由、通知和申诉记录；不因每日签到、学习时长或暂离自动收回长期席位。

活动与维护先做影响分析，必要时改时间、改地点或提供符合条件的临时替代使用权；原长期归属保留。学生反馈仅本人及负责管理员可见，确认后的维修/环境信息按规则公开。

### 图书馆活动

获期序授权的老师和管理员可创建读书会、公开课、讲座等活动，填写介绍、场地、时间、人数和报名期限。学生查看活动并预约参加、取消报名、查看通知；活动报名是参与资格，不等于个人长期席位或独占整个场地。

老师默认仅管理自己组织的活动，空间审批者依管理范围确认场地和影响；外部身份的“教师”标签不自动授予期序管理权。只有场地使用权批准且活动条件有效后才能发布。活动改期、换地、取消需要重新处理空间影响并通知已报名者，不能修改一段展示文本而保留旧占用。第一版不扩展社团、群聊、付费票务和教务课程系统。

## 端与视觉

学生端 uni-app 微信小程序，暖米白与克制朱砂红，照片帮助理解空间；书法仅用于品牌，常规正文便于阅读。管理端 Vue 3 + TypeScript，灰白/灰绿为主，地图、时间与冲突清晰。

手机管理支持待办、单项审批、反馈处理与现场处置；大规模配置由桌面承担。返回保留筛选、日期、搜索、分页和滚动；键盘、安全区和操作结果恢复需要实际验证。

参考图是视觉方向；长席位“去选座”改为填写志愿，删除分配机制开关；已分配与使用中分开，地图可用状态绑定日期和时段。不以图中未实现控件承诺功能。

## 当前不做

大模型、支付、学习排行榜、连续签到积分、座位评分榜、摄像头、人脸识别、物联网实时占用、GIS、微服务拆分和默认消息中间件。双方换座、复杂课表周期导入、多部门自动集成放后续版本。

## 实施细节与保守默认

| 细节 | 第一版方向 / 尚需阶段证据 |
| --- | --- |
| 学生身份依据 | 演示环境明确的学生记录；外部账号有效不自动等于在校学生 |
| 随机来源 | 固定未来公开来源；不可用时等待同一来源，不改种子；完整来源验证方式在 M1 定义 |
| 资格/志愿/确认期限 | 批次显式配置并在冻结前公开，不能临时倒改 |
| 短期到场确认 | 用户自报，非物理在场证明；宽限与释放规则提前展示 |
| 活动优先级 | 不预设任何活动自动覆盖既有使用权；须显式处置影响 |
| 初始身份接入 | 独立演示可运行；暗室身份适配需按真实接口和失效场景验证 |
| 发布范围 | 独立公开仓库、可复现源码；微信认证与生产部署不假称完成 |

## M0 退出条件

仓库和名称明确，长期分配、候补退出、空间申请、占用冲突、图书馆活动五份业务合同包含不变量、正常链路、失败边界和验收场景；里程碑可追踪，参考风险与真实失败区分；没有虚构可运行产品、运行截图、测试结果或外部集成完成声明。

期序不以“通过 VeriTrail”为开发目标；期序按自身业务合同成立，验迹约束其公开完成声明不得超过可观察证据。阶段顺序是合同、实现、项目自身验收、固定候选坐标、验迹资格与公开读回，最终发布处置保留给项目所有者。每个阶段的 Claim、Evidence、Stop condition、VeriTrail boundary 见 [里程碑](milestones.md)；不是先生成验迹配置再倒推业务。
