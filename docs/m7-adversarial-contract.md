# M7 · 组合攻击与错题复核合同

用户明确要求“还不够多、不够狠”，M7负责扩展失败空间。现有反例矩阵只是种子；实现完成后从固定候选重新研究公开问题，不用现有测试数量充当完成条件。之后M8才交给两名独立测试/产品审阅者。

## 方法

每条攻击记录：前提、攻击步骤与调度、预期不变量、真实观察、首次输出、最小反例、分类、修复坐标及原合同复验。正常拒绝不是产品失败；测试自身错误、依赖不可用和未观察分别登记。公开案例要有原链接/版本，不能只记模型想象或把别人的PASS迁移到期序。

除了端点输入，攻击整个操作序列。以独立小规模业务模型/穷举匹配作oracle，比较真实HTTP及MySQL终态；不要只比较实现自己的两次输出。失败序列缩减为最小可复现trace，保留seed、服务/迁移版本、时间和调度坐标，修复后重放原trace。

## 扩展方向

| 维度 | 必须寻找的更强反例 |
| --- | --- |
| 算法 | 全枚举小图；并列偏好/空边/全接受/极不对称；输入容器重排不变；更严格硬条件不能突破；结果达K；公开独立复算；身份编号/申请早晚不得隐含加权 |
| 截止组合 | 修改→锁等待→截止→冻结；确认→释放扫描→响应丢失；freeze晚于beacon；候选算完但publish迟到；时钟边界与相邻周期；不拿sleep代替时刻/锁证据 |
| 网络 | 请求未到、在途、commit后丢响应；重复并发/重排；查询早于commit；503与404交替；重试预算耗尽→恢复登录→同actor；A→B后旧成功/401/Set-Cookie |
| 权限 | 管理范围在等待期间撤销；actor/space/floor篡改；userId同名跨provider；teacher→admin诱导；过期外部身份租约；拒绝路径无业务副作用；公开复算/反馈无身份泄露 |
| 多业务组合 | 普通位与长期offer；兜底升级与新短约；两重叠batch；整区block与子座；活动换地与审批取消；容量变更与最后参与名额；临时替代结束仍有另一维护 |
| 事务恢复 | 实际事务中途异常；候选持久后进程停止；完整发布后进程停止；任务重复/恢复；deadlock/连接失败有限预算；旧attempt/扫描不能获得新提交权 |
| 备份及外部副作用 | 恢复前后generation；独立交付账册；旧正式通知与恢复库矛盾；没有外部账册时必须NOT_RECONCILED；恢复不能自动重发/重分/重新宣称公平 |
| 数据/协议 | 大小/空值/Unicode/类型/无offset时间/重复对象键；页码边界；错误码和requestId；唯一/FK/check约束；低权限账号不能写其他schema；日志无票据/秘密 |
| 前端 | 慢旧读覆盖新写；旧角色导航；409保草稿；UNKNOWN不清除；浏览器前进后退及直接链接；窄屏/缩放/键盘；错误、陈旧、空结果分别投影 |

每项至少考虑两种失败叠加；针对新发现增加三方竞争及不同事务边界。测试预算有限时优先攻击能产生错误使用权、越权、无声丢申请或伪正式结果的路径，不能只增加无意义坏字符串数量。

## 覆盖账册与独立判定

M7执行前再冻结攻击账册，逐条绑定候选SHA、迁移校验和、前置数据、调度和oracle。沿下列事实链各找能推翻声明的例子：身份→提交版本→冻结输入→候选输出→原子发布→有效使用权→实际足迹→递补→通知→查询→恢复。把每个事务边界的「之前失败、提交中失败、之后丢响应」分开，不能用一个timeout例替代三者。状态相同但来源不同、时间相同但接收顺序不同、结果相同但权限已变，也要分别检查。

优先组合的具体trace：

- 截止前两次修改互相锁等待，第一次响应丢失，第二次越过截止，再与冻结竞争；观察唯一冻结版本和原键回执。
- A发出写/查后切B，再使A成功、401、旧cookie控制依次晚到；B页面、凭据和未知请求不得漂移。
- 已有普通兜底、安静位offer、第三人短约和区域封闭同时竞争；只能产生一份合法最终权，失败保持原兜底。
- 管理员预览后范围撤销，再与影响减少/增加、设施变坏及活动换地竞争；旧摘要与旧权限都不能授权提交。
- 原子发布前后停止owned进程，恢复任务重复，再使通知失败；不能产生部分正式结果或第二轮随机选择。
- 维修WORK_DONE与学生补充/重开、另一个来源未解除及原图读取竞争；修理声明、公开条件、限制和私有图片分开判定。
- 通知已在外部留痕后恢复旧库，再启动任务并重放旧幂等key；必须识别世界未回滚，未对账不能重发或重分。
- 低权限读、旧缓存、分页截断和公开复算同时存在；不能因筛选/摘要遗漏而泄露主体或声称完整。

每条除了正向链还要有拒绝无副作用、相邻时间边界和同键重放对照。至少为不同调度顺序、三方竞争和预算耗尽保留独立记录；优先级按错误使用权/越权/无声丢事实/错误完成声明排列，不按HTTP请求数排列。

分配oracle使用独立穷举小图；权利oracle按半开区间、空间祖先和来源足迹自行归约原始SQL；权限oracle从当时有效身份/范围事实推导；通知oracle对结果集合逐人核对持久站内通知；前端oracle使用实际路由/可见主体/请求键和服务器事实。不得直接调用被测Service作期望值。账册为每项明确PASS、正确拒绝、FAIL、环境阻断或NOT_PROVEN；未执行、不支持、只有模拟、只有构建均不得填PASS。

公开错题只作为启发，不作为完成凭证。M7需在实施后重新搜GitHub问题/修复/复现用例，并将每个有效来源转成期序的最小反例；再从来源反推未被提及的邻近组合。M8独立角色必须能从账册和原trace重新挑战结论。尚存P0/P1、无独立oracle、原失败丢失或边界不公开时，不得退出M7。

## 停止与退出

使用隔离schema与本项目owned端口/进程；物理故障演练另建本项目独占MySQL实例，绝不停止宿主共享MySQL或其他Java服务。公开随机源只读且有预算，不对无授权外部服务做扫描/爆破。安全扫描插件不是此阶段前提。

出现双权、冻结篡改、伪签名发布、身份泄露、共享资源被影响时立即停止该攻击、保存证据并缩小修复。原始失败不得删除或靠放宽断言通过。修复后重放最小trace及受影响邻近组合；全部完成后按当前候选给出已验证/明确拒绝/边界/尚未证明清单。

M7退出不宣称穷尽所有缺陷。退出要求：新公开错题与新本地组合有证据处置；阻断反例已修并复验；剩余边界与公开声明相符；才将固定坐标交给M8独立角色。VeriTrail封存Plan后消费实际测量，测试者自评与绿色CI都不替代裁决/交付资格。

## 按失败机制收束，保存未知

2026-10-03用户补充：M7不追求绝对不存在Bug；想到的尽量补，想不到或无法验证的仍须可追踪。攻击范围在M7执行入口冻结，按失败机制归并同类排列，不能仅凭请求数或测试数结束，也不无限增加低收益同类排列。

使用[覆盖账册](m7-coverage-ledger.md)记录每种机制的核心不变量、最小trace、代表性组合、首败、修复候选和复验。每个入口项必须有处置：已验证、正确拒绝、已击穿待修、明确能力边界或NOT_PROVEN；PLANNED/缺记录不算已处置。新机制出现时扩展对应项并复验邻近组合，不重启全部已闭合领域。

退出判断依次为：

1. 已声明核心不变量有针对性反例与独立事实判定；关键单故障和组合分别覆盖，原始击穿按原标准重放。
2. 新公开错题和来源之外的本地启发已分类，没有遗失或把测量错误计成产品修复。
3. 没有范围内尚未处理的错误使用权、越权、无声丢事实或伪正式结果。单纯写NOT_PROVEN不能掩盖已观察到的核心缺陷。
4. 剩余未知各自保存触发条件、可能影响、缺少证据、为何当前不能验证、重新进入的命令/合同/环境入口及跟进归属。没有能力支持的生产多节点、长网络分区等不冒充通过。
5. 重复排列未发现新机制时可停止该类扩展，说明代表性调度与遗漏；将固定候选和整个账册交给M8，两名独立角色可以重新挑战边界。

未知项默认跟进归属为期序维护者，不能只写“以后再说”。后续出现对应部署能力、新依赖版本、实际事故或独立角色发现新机制时，重开最小相关项。M7交付回答“攻击过什么、击穿什么、修过什么、还不知道什么”，不输出“零Bug”或“绝对安全”。
