## 上游协议与身份坐标

参考公开固定 [DarkRoomLibrary@d6e42a81d3eb83ed483553b7319bbe55dceb8c7f](https://github.com/NoctilumeDev/DarkRoomLibrary/tree/d6e42a81d3eb83ed483553b7319bbe55dceb8c7f)，不复制为脚手架、不修改其他项目。接口是 `GET /api/dark-room-library/v1/user/auth`，使用 `Authorization: Bearer <ticket>`。拦截器核对有效账号及当前 authVersion；成功返回整数 `code:200` 和账号 data。

要求正整数 id、整数 accountStatus=0、布尔 isLogin=false；isLogin 是上游“禁止登录”标志，false 才表示允许。姓名/email/userRole/coordinatorAdmin 不转换为期序权限或学生资格。缺字段、错类型、重复 JSON 键、无效 UTF-8、超长响应均不构成证明。401/403/明确停用是拒绝；超时、跳转、429/5xx、错误协议是依赖未知，结构化503，不把未知当有效或永久撤销。

## 绑定与票据

- provider 固定 DARK_ROOM_LIBRARY，subject 是已验证的规范十进制 ID。操作员显式登记 `(provider, subject, issuer fingerprint) → local user`，无自动建号/合并/提权；同名或同数字不授权。
- 绑定有 active/version/issuer。解除、改绑或改端点后旧会话不漂移；操作原因留审计。新增绑定默认关闭，历史行不自动有效。
- URL 仅来自受控配置，固定绝对 auth 路径，无 userinfo/query/fragment；生产 HTTPS，显式本地集成才允许 loopback HTTP。不跟随跳转。请求不接受 URL、subject、role、scope。
- 票据至多4096字符、连接500ms、完整响应2秒、响应体32768字节、并发4，兑换入口每来源每分钟最多20次；网络始终在数据库事务及空间锁外，饱和503，不无限排队。
- 暗室密码不进入期序。兑换获得期序 opaque session，只存摘要；为持续校验，上游票据由独立环境密钥 AES-256-GCM 加密，随机 nonce，AAD 绑定 session摘要/本地主体/绑定版本/issuer。缺密钥不启用；密文篡改/错密钥关闭。票据/密钥/Authorization/个人档案不得进入日志、审计、公开证据。
- 外部专用本地主体关闭密码登录，防止绕过上游停用。既有 demo/本地主体独立登录；操作员显式选择外部专用模式，不顺手停用已有用户。

## 会话及写入资格

外部会话每次认证都重验当前上游身份，第一版没有离线缓存或宽限租约。未知时读写均明确不可用，业务和原 key 不改变；登出清理自己的期序会话可以不依赖上游。

认证产生当前请求专用短证明，最大年龄3秒，从本次网络请求开始计（同时使用Clock与单调时钟），不把慢响应耗时加在年龄之外。网络结束后再读本地 session/active/authVersion/绑定版本/issuer；写事务取协调锁后再核同一坐标和 Clock。证明过期503并回滚，不在锁内续验。上游明确拒绝可撤销该会话，排队旧请求在提交检查处也拒绝。

不保证跨系统瞬时撤权：证明之后才发生的上游变化存在本次短窗口的观察差；公开保留此边界，不冒充分布式事务。Cookie继续受Origin/CSRF/文档所有权约束，Bearer异常不回退Cookie。

## 恢复事实

1. MySQL已提交、响应代理丢弃：客户端保留UNKNOWN及原key，恢复查/重放得到同一回执，业务/审计/outbox一次。异体同键409，旁人不能读回执。
2. 固定候选JAR提交后重启：同一专属数据库保留业务/回执，就绪前503，之后一致；不清库倒填。
3. outbox提交而未投递：恢复有界重投，同事件只产生一个应用内消息；DELIVERED不代表READ。非真实微信推送证明。
4. 冻结分配恢复：同input/hash/algorithm/future round、正式结果唯一，原公开包在干净检出复算；不得换seed或冒用替身。
5. 未知有原请求/时间/进程/候选坐标及恢复入口。数据库故障在专属连接/进程注入，绝不停止共享MySQL。

停止进程前核对PID、启动时间、可执行文件、命令行和产物路径，不泛匹配java/python。归属账册不含凭据。进程重启不证明“备份回滚后已发外部副作用”的自动对账。
