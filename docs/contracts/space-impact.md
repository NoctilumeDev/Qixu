# M4 空间影响实施细则 · 0.2

先于 V5 实现冻结。继承 [M4 合同](governance-implementation.md)，本文件规定协调与计算边界，不声明功能完成。

## 来源与时段

`space_block` 独立记录 MAINTENANCE / SAFETY / COURSE / EVENT、原空间、半开窗口、理由、创建与撤销。EVENT 必须绑定明确场地申请；COURSE/EVENT 是独占占用，MAINTENANCE/SAFETY 是可叠加限制。长期原使用权不修改 spaceId，`long_temporary_arrangement` 逐来源记录原 offer、受限的实际位置、替代位置或明确不可用、窗口。原 offer 未到期且 OPEN，或其 ACCEPTED 且原 entitlement 仍 ACTIVE，临时记录才有预留效力。

计算器读取独立原事实，把查询窗口按原权、Block、临时安排边界切成半开片段。从原位置逐层检查：当前位置上的每个有效限制都须有该原权的覆盖处置；重叠处置必须指向同一替代（或同一明确不可用）。然后检查替代上的限制。无处置、矛盾、循环、超过 8 层都是拒绝条件，不猜最新安排。限制结束/撤销后重新推导，不写 AVAILABLE。安全维护允许明确无替代；计划课程/活动不允许以无替代覆盖长期权。

只产生发生限制的窗口内替代权，原权在其他时段继续有效。临时预留在原 offer 到期、拒绝、退出、升级关闭原 entitlement 后实时失效，不依赖任务及时执行。一般查询也要看跨层替代事实，不能只查本层原表。

## 协调和有限处理

原业务状态机仍各自独立，协调锁不赋予领域权限。为安全处理跨层替代，空间写动作的 floor 集合扩展到历史临时映射形成的连通分量，再升序锁定；取得后重新计算，若出现尚未锁住的关联层则 409，重新预览/重试，不逆序追加锁。新增映射必须同时锁原层和目标层，旧映射不删除。最多 64 个关联楼层；超限明确拒绝，不截断。

活动仍 event → floor → user，长期动作仍 batch → floor → user。Block 不在持有 floor 后请求 batch 或 event；为冻结影响摘要内的申请人集合，先按 ID 升序锁涉及 batch，再按 ID 升序锁涉及 event，然后扩展 floor。锁后重新发现若多出 batch/event/user 则 409。涉及使用者及活动参与者先收集、锁后复核完整集合；未知坐标不现场添锁。0.2 在实现前补明申请提交不持 floor 的协调反例，不改任何已实施迁移。

每次影响计划窗口 ≤30天，最多 500 个有效权片段和 2000 个批次保护片段、2000 个相关通知对象；超过拒绝。查询计算最多 5000 个相关原权/限制/临时记录，所有读取先检查总量，绝不 LIMIT 后把截断结果冒充完整。该上限是产品首版边界，不是生产容量资格。

## 预览与提交

预览完整绑定计划、源和替代空间版本、原权版本、有效时间边界、所有限制/安排及其版本、批次状态、活动状态/版本/参与者和通知对象。摘要 SHA-256 规范化编码，不接受客户端填写影响对象代替数据库发现。变化包括新增、减少、到期、撤销或换地，都令旧摘要失效。

提交先以原 key/body 找已提交回执；未提交方案取得协调锁、重新权限与摘要核对，每项影响都有且仅有合法处置。短约可明确取消；迁移创建新短约并关闭旧记录，保留 typed 来源链；已批准场地可取消或经原组织者另提申请后换地，报名关系按事件合同保留。长期要约/权临时替代留原归属。池保护不等于有人拥有；资源变化通知申请人但不修改 frozen input/result。

临时目标设施至少满足原空间公开 features 的 true 条件，不在受保护池，不与其他权、课程或限制冲突。对同一方案的目标也逐个检查，后一个不能和前一个占用同一时间。完整处置、Block、安排、必要的新权、通知、审计在一个事务；第二个通知失败全部回滚。最终写入再次核对当前时间，不接受已经结束的计划。

`APPROVE_WITH_RESOLUTION` 必须绑定当前待审场地、版本、精确空间和窗口。Block 与场地批准同事务，普通 approve 仍拒绝冲突。该来源只能随其场地/活动变更或取消撤销，不能单独撤销以留下没有场地保障的公开活动。冻结批次仍由原 M3 当前校验整轮失败，不暗改池或重抽。

## 学生确认

我的长期要约展示当前影响、每段原位置/临时位置/不可用、期限及 impactHash。无影响保留 M3 接口兼容；存在影响时 ACCEPT 必须带当前摘要。摘要变化 409，不延长原期限、不释放兜底、不代替学生接受。确认检查实际足迹与自身原 offer 排除，BATCH_PROTECTION 仅在本 offer 原池内排除；临时目标仍不能侵入其他池。历史回执重放先于新事实检查，期限后仍能确认原动作是否曾提交。

## 必须观察的反例

父区限制与子席写入并发；旧预览在新增/到期后拒绝；跨层两个计划争同一替代；两限制同源兼容、撤一保留另一；替代再次封闭；取消上游后下游不虚占；OPEN offer 到期即时释放临时预留；旧 impactHash 不接受；原权/原结果不改；事件取消只撤自身来源；通知故障原子回滚；floor 等待期间撤权；新关系导致重试而非补锁。

这些是义务。施工测量、M4 sealed Plan、独立 M7 序列反例分别留证，不以文档或测试数量代替阶段资格。
