# 短期预约、空间申请与反馈合同

状态：M0 业务基线。共享空间信息和冲突计算，分别保存业务状态。

## 空间信息

空间有固定标识、物理位置、容量、设施、入口条件和开放规则。缺失设施数据是未知，不默认“没有”；描述与测量事实分开。图片为演示示意时明确标注。可用情况绑定查询时间，不假称实时有人/无人。

普通自由使用区不强制预约。可预约普通区按当天/短期窗口预约；不制造每天固定时刻开抢。活跃备考区由对应批次管理，普通身份不得绕过规则预约未分配备考位。

## 短期预约

正常链路：查询条件 → 提交预约 → 获得待到场预约 → 到场确认 → 主动结束或期限结束。宽限和最大时长先展示；未到释放只针对本次短期预约，不扩大为长期资格处罚。

预约覆盖完整开放时段且符合资格、设施、个人时间冲突及资源冲突规则。相邻时段按半开区间判断；容量、期限和请求幂等在数据库事务内最终确认。

到场确认是用户自报，不能声称证明物理位置。历史记录、回收/关闭等状态与当前可用分开。

## 教室与场地申请

申请包含空间、时间、人数、用途、设施需求和联系人。申请提交与批准占用分开：待审可以存在多个重叠请求，不产生已获准使用权。

审批人受空间管理范围约束。批准前重新计算全时段及空间层级冲突；冲突未解决不得直接批准。批准和占用事实同事务完成，通知是提交后的可恢复副作用。

拒绝/取消有理由；修改已批准的时间、空间或人数重新经过校验，不能复用旧批准绕过新冲突。业务未知结果可按请求标识查询，重试不重复创建。

## 空间反馈与维修

学生报告插座、桌面、台灯、环境或资料不一致等问题；原始反馈仅本人和负责空间的管理员可读。图片访问同样检查权限，不通过公开静态 URL 泄露原图。

反馈待核实 → 核实中 → 处理中 → 复验后解决；暂未确认和不予处理需要说明，保留补充/重新打开入口。未复现不等于虚假反馈。

确认问题后可建立维修事项，重复报告关联同一维修事项，分别通知提交者。是否关闭空间需根据影响单独决定；不能由学生单条报告自动封闭空间。

维修完成与复验通过分开，确认恢复后更新档案/维护状态；公开层只展示确认后的设施或环境事实及复核时间，不展示提交人或私密图片。

## 关键验收

- 双击、重复请求与提交后断网不创建重复预约或申请；相同幂等键不同正文拒绝。
- 两人同空间重叠预约、同人不同空间重叠预约、两管理员同时批准保持一致。
- 过期、禁用身份、越界管理员和仅能查看的主体不能写入业务。
- 原始反馈与图片权限隔离；学生反馈不直接改变公开事实。
- 维修已安排不显示已解决；复验失败仍可继续处理。
- 手机返回保留上下文，网络错误有恢复入口，键盘不能挡住必要操作。
