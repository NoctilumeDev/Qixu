## 坐标与必需证据

新增 `qixu-native/0.9` 的M4 Plan1，subject为exact clean SHA。保留原M1/M2/M3采集器语义与版本，M4不伪装成M3。先seal，再执行Maven clean verify；XML必须包含原52项及FeedbackIT的9项、SpaceBlocksIT的29项、GovernanceCasesIT的20项，名单在可审阅采集合同中逐项固定。遗漏、跳过或重复用例不能被最后一个同名记录覆盖成成功。

必需测量来自同次fresh测试生成的六份观察文件，记录真实HTTP状态、直接SQL及公开设施投影；缺文件、缺字段或解析冲突不是零。JAR记录本次构建源、大小与摘要，执行前后均需干净且同一SHA。文件来自期序采集器，不宣称Core取得MySQL生命周期控制能力。

## 直接事实要求

每项M4观察结束后读取独立SQL统计，不能从测试PASS或业务Service返回值推导：

- 具有收回版本的案件中，`decided_at < statement_until` 的数量为0。
- 已复核案件中，`reviewed_by = decided_by` 的数量为0。
- 同一用户的两项ACTIVE长期原权在各自批次半开周期相交的数量为0。
- CANCELED批次具有任何长期权历史的数量为0；已退出仍是历史，不能只数当前ACTIVE。
- 长期权与来源offer的batch/user/space/floor坐标不一致的数量为0；临时实际足迹不得改原归属。

治理用例另外直接保留案件、原权、处罚、批次及要约状态集合；不公开用户映射/私有陈述。恢复与无法恢复、原权被他人合法递补、等待中撤范围、无人持权取消均要绑定实际状态。并发裁决允许两种合法赢家，不硬编码哪位管理员获胜；SQL仍必须只有一条正式裁决。

通知故障必须在恢复前采集回滚状态及该键的回执数量，恢复后再采集终态；不能仅凭恢复成功证明先前完整回滚。报告/附件/事实与维修现有测量中的常量改为直接SQL或实际响应状态。空间限制至少绑定回滚后无新限制、原权坐标保留、各来源状态、维修只撤自己的来源及既有结果不被覆盖；已有用例内直接断言保留。

在新identity中对真实留存证据删除必需M4观察字段、篡改一个SQL不变量，分别验证Core判缺证据/FAIL；控制不得修改原Bundle，也不是产品故障。之后同标准新执行身份正常复验。先前维修首败、错误路径导致的无效PASS和全部施工失败继续留存。
