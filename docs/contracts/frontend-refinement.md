# M10 · 前端精修与验收合同

版本0.1 · 2026-10-03。用户明确新增M10：当前轮先保证前端能用、素材正常且充足、结构合理，不急于视觉精修。此变更划分验收阶段，不取消工程步骤。

## M5与M10的分工

M5负责关键业务从真实页面走通、素材能展示、信息结构清楚、桌面及手机可操作。阻断操作的遮挡、丢输入、错主体、错误状态、未知提交丢失、错误空结果、私有照片泄露和返回上下文丢失仍在M5修复；不因后置精修而接受这些问题。

M10负责最终视觉完成度：学生端暖米白/克制朱砂与空间摄影，管理端低饱和灰绿与清晰密度；统一字体、层级、留白、边界、图标、图片裁切、状态标识、焦点、加载/空/错误/未知表面。素材保留示意声明，不把生成图片称为真实馆内照片。无需逐像素复制海报或把海报文字搬进业务流程。

M8产品经理先检查业务结构、可理解性和可用性；可将不阻断的视觉问题列入M10。M9形成公开工程候选，明确精修待验；最终项目与前端完成声明在M10之后才可成立。

## 执行与证据

1. 从M9固定候选、当前业务合同和用户选定两端原图恢复目标，先登记各页面结构与待精修项。
2. 使用真实后端页面，捕获相同状态的桌面、390px手机、窄屏和缩放。把原图应用内容与实际截图规范化放在同一比较输入；海报场景、设备边框和虚构数据差异单列。
3. 保留首次比较、优先级、修复坐标及同视口复验。在`design-qa.md`维护历次比较；影响最终视觉质量的P0/P1/P2处理后再声明通过。
4. 覆盖键盘操作、可访问名称、文本与颜色双重状态、图片失败、滚动、地图选择、前进后退、表单与提交区。桌面重配置和手机现场审批遵循同一业务语义。
5. 精修不能修改后端公平、权限、截止、使用权、未知提交或通知合同。若必须改业务，重开最小对应合同并重验，不作为纯视觉修改偷渡。
6. 对精修后的固定候选执行受影响业务回归、干净构建、真实页面和MySQL事实核对；封存适用验迹Plan，保留实际Evidence/Bundle/裁决及公开CI读回。最终截图、README、main与Release必须对应这一候选。

微信键盘、订阅消息和真机行为必须分别留实机证据；只观察H5或只编译小程序时标记NOT_PROVEN。缺设备证据不得迁移浏览器资格。现实空间、维修执行、生产容量与未接入校园身份不因视觉验收而获资格。
