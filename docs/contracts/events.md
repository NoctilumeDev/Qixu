# 图书馆活动、场地绑定与参与名额合同 0.1

状态：M0 需求候选；活动为一等对象，不能简化成 SpaceBlock。

## 事实所有权

`Event` 拥有活动名称、类型、主讲/组织者、介绍/海报/注意事项、时间、报名窗口、参与上限、发布版本与变更记录。`VenueBinding` 指向经审批取得的空间使用权；`Participation` 保存学生确认名额或候补关系。三者分别保存，不共享一套预约状态机。

期序直接组织的读书会/公开课/讲座由期序维护活动及参与事实。青野来源申请只取得场地绑定，青野继续拥有社团和参与业务；不复制其成员/报名表，不让来源自行授予空间权限。外部事件接口按来源和事件键去重。

## 创建与发布

老师须有期序授予的组织权限。默认可维护本人活动并申请被允许的空间；空间审批者仅能在管理范围内批准。组织权限不等于场地审批权。

活动草拟 → 关联场地申请 → 检查时间/容量/用途/层级占用并完成审批与影响处置 → 发布。发布必须事务内重新确认场地批准仍有效、时间一致、容量合规且无未处置冲突。`PUBLISHED` 与绑定不得只在两个独立请求中先后拼凑。

活动人数上限不超过已批准空间容量。已冻结或生效的场地容量不能被后续编辑缩到确认报名数以下而无处置。活动发布/改期/换地/取消均带版本和幂等请求；过期页面写入拒绝并提供刷新恢复。

## 学生预约与固定候补

在公开报名窗口内，学生可取得 `CONFIRMED` 参与名额；满额进入 `WAITLISTED`。队列顺序由数据库串行确认的报名序号决定，排序字段不是可由客户端指定的时间。第一版普通活动实行公开窗口与请求顺序，不冒充长期席位公平抽签。

同一学生同一活动最多一条有效参与关系；重复提交不重复计数。确认数永不超过公开上限。取消确认时，同事务中按原队列选仍有效、未退出的首位候补自动递补并记录事件；消息可恢复，但不能影响递补资格事实。

候补退出、再次参加均留历史；再次报名按新序号排队，不恢复已放弃的旧优先位。报名关闭后不接收新报名；已有候补是否继续递补由发布前配置的 `promotion_until` 决定，且不能晚于活动开始。不存在报名关闭后管理者临时插队的入口。

活动预约不替代个人短期预约或长期使用权。学生在详情看到时间冲突提示并可主动取消个人短约；参加活动不证明物理到场，不自动收回长期座位。第一版不为活动分配图书馆具体固定桌位。

## 状态与有效时间

生命周期对用户呈现 `DRAFT → PUBLISHED → REGISTRATION_OPEN → REGISTRATION_CLOSED → IN_PROGRESS → COMPLETED`，适用阶段可进入 `CANCELED`。时间阶段可由已发布事实及服务器时钟推导，避免调度延迟让截止后仍能报名；持久化事实、阶段投影和取消原因分别说明。

所有报名/递补/改期按服务器时间和当前版本最终校验，不能以客户端时钟或过期按钮显示授权。

## 变更与冲突

维护或活动占用引发场地冲突，建立明确 Resolution。老师选择换场地、改时间或取消；不能直接改一个 SpaceBlock 后偷偷重写学生参与记录。

仅换场地且时间/参与容量未变：重新获得合法绑定，保留报名/候补关系，通知变更并展示新位置及无障碍/设施信息。原绑定释放和新绑定生效为原子操作。

改时间：新时间重新审批，保留变更前事实及参与关系，通知学生并允许取消，不将旧报名当成已接受变更的证明。若需缩减参与人数，第一版拒绝直接修改并要求明确方案或取消重发；不静默挤掉后报名者。

取消活动：活动及自身场地占用关闭，报名/候补变为活动取消历史，发通知；其他人的座位使用权、其他活动及原始审计不被删除。

## 必须观察的反例

- 两学生争最后一名额、取消与新报名并发、自动递补与候补退出并发，确认数和队列顺序仍正确。
- 老师编辑他人活动、越界场地审批、未获批准直接发布、过期版本重试均拒绝。
- 发布后场地许可被处置、替代空间不可用、报名已满后的容量缩减，不出现展示与权威事实矛盾。
- 换场地不丢报名；改期保留历史并通知；单人取消只释放其名额。
- 报名、通知、审计失败分别定位；提交后未知结果按幂等标识查询，不能重复占名额。
- 首页近期活动、详情、空间档案链接、我的预约/候补状态和老师待办实际可用。

不实现社团、问卷、照片墙、评价社区、积分、收费或教务授课记录。
