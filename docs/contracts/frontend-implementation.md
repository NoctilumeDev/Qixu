## 请求所有权与恢复

0.7进一步区分请求尝试与幂等意图：新尝试收到明确4xx并不证明另一个在途同键尝试未提交。当前主体仍有效时，自动取得原子停止屏障或原回执后才清除恢复记录；已提交则采纳原事实，屏障成立则展示原拒绝并保留表单。屏障失败/身份失效时保留未知键，禁止新意图，不能按HTTP状态本地抹除。原先未知的重试拒绝仍需显式恢复，不自动停止用户原意图。

0.6保留双文档持久化首败：待确认意图改为逐键不可变存储；创建时先保存再发送，网络状态只改变内存。退出、清私有正文和其他文档变化不重写全量数组；提交回执仅删除该主体该意图。晚到失败不得重新写入已经删除的记录，重载按逐键元数据恢复；敏感正文从不持久化。存储失败必须在发送前明确拒绝，不伪装请求已发出。旧格式仅首次迁移，格式标记后旧数组不再成为事实入口。跨文档刷新只合并仍存在的记录，不能清掉另一页未知意图。

0.5由真实双标签页首败触发：Cookie绑定的是浏览器共享会话，JS generation只属于一个文档。已有X-CSRF-Token在Cookie读请求中同时作为观察主体的会话绑定；携带但与当前会话不匹配时返回409 SESSION_OWNER_CHANGED，不能返回新主体私有数据。auth/session是冷启动事实核对入口，不强制旧绑定；无绑定的传统只读调用保持服务器当前Cookie授权，不能获得旧文档投影资格。Cookie控件操作（含不确定结果）广播不含凭据的失效信号，其他文档清除旧投影并停止读写直到重载。广播是及时清除的增强，服务器绑定是读请求底线；不依赖广播赋权。当前文档显式bootstrap发现主体或Cookie会话变更时提高generation再接纳新会话；在途旧响应不可越过它。主体绑定失败/旧CSRF使页面停止控制和业务写，不清除原主体待确认键或臆测撤销。Bearer读保持自身token授权。

- 登录/登出/会话变更串行，generation变更清空当前主体数据；GET捕获generation及加载序号，旧响应不覆盖新主体/新筛选，旧401不退出新会话。
- Cookie登录控制本身丢响应时，不在同一文档继续切换账号或业务写；清空当前投影并提示重载，再以真实session核对身份。串行JS回调不能撤销浏览器已接受的Set-Cookie。
- student Bearer与admin HttpOnly cookie+CSRF分别传输。小程序token不放URL或日志；H5和admin开发代理同源，不用通配凭据。
- 有副作用请求发送前保存actor、path、不可修改原DTO、幂等key及状态。超时、断网、5xx、无法解析成功视为UNKNOWN；界面持续显示恢复入口，GET成功不能清除它。receipt404不解释成未发生；有限同键重放或查询，不能换正文/换actor恢复。不同意图先处置原未知动作。
- 请求键、会话及草稿按主体隔离；未确认记录重载仍可恢复。未知记录最多16项；不能以清理本地记录撤销服务器使用权。敏感反馈/依据正文只在内存，离开/退出清除；仅保留actor、path、key、createdAt和不可重放标记。重载后敏感请求只能查询回执或原子停止，不凭空重建正文。
- POST `/receipts/{key}/stop` 在当前主体行锁内，与所有原业务写使用同一串行化点：已有回执则返回原事实；无回执则持久化 `client.intent-stop` 屏障回执，明确 `STOPPED_WITHOUT_EFFECT`。后到的原请求同键冲突，不能产生业务效果。屏障只停止本主体该键尚未发生的意图，不撤销已成立的预约、申请或使用权，不接受目标主体或正文；重复停止返回同一回执。404、前端超时、本地删除不替代屏障。页面区分“原提交已成立”和“原意图已安全停止”。
- 401重新登录并保留同主体恢复路径；403范围说明；404父入口；409保留输入、明确版本/空间冲突并读回；422定位字段；503重试且不把旧数据标成新数据。普通读错误、未知写、确定拒绝分区显示。
- 每个业务写最终从返回回执+详情读回成立；成功回执是历史事实，不能覆盖详情当前状态。

## 上下文、时间和输入

路由保存筛选/搜索/日期/选中层及滚动；详情返回保留原上下文，直链有父入口。前端按Asia/Shanghai显示，业务输入转含offset且秒精度；服务器Clock裁决。日期跨UTC不改变用户选的本地日；无效输入不发请求。
