# M2 短期预约、场地和活动实施合同 0.1

前置为 M1 独立 MySQL、会话和空间档案。先冻结本合同再实现追加 V2；本页不是执行结果。

## 范围与规则

普通短约仅针对单座，服务器上海自然日 08:00–22:00 开放；开始在当前时间至未来 4 小时内，完整时段同日且最长 4 小时，时间精度到秒、半开区间。开放规则展示在 API/页面，之后修改规则不得重算旧预约期限。备考区在未被批次保护时允许短约，M3 增加批次窗口保护；本阶段不声称长期权已生效。

取得预约为 PENDING，`check_in_deadline=start+10 minutes` 且不晚于 end。本人可在 start 到 deadline 之前自报到场，进入 CHECKED_IN；不能提前确认。PENDING 超过 deadline 即无效，CHECKED_IN 到 end 即结束。本人可提前取消或结束；历史保留，失约不累积努力/惩罚积分。

同座、同主体的有效短约不能重叠；场地批准占用与其父/子空间短约不能冲突。待审场地申请不占权；拒绝/取消留理由，审批需当前 version、空间管理范围、完整时段和人数不超过容量。学生可申请研讨/活动空间，老师和管理员可组织活动；任何组织角色都不能绕过场地审批。

场地申请 1–200 字用途、1–500 字说明，人数至少 1；开始需未来、跨度不超过 1 天、完整时段在开放时间内且在未来 30 天内。批准产生独立 venue_entitlement；关闭只释放该申请的占用。已批准改期/换空间经新的申请和批准，不直接改旧使用权。

活动草稿关联组织者本人申请，主讲/简介/注意事项分别存。发布需该申请有效 APPROVED、场地容量合规、当前版本无冲突；参与上限不超过批准人数。发布后改时/换地通过新的已批准申请原子换绑定，保留参与关系；第一版拒绝缩减参与上限，允许明确取消后重新发布。报名开放/截止/递补期限保存 UTC，`open < close <= promotion_until <= start < end`。

参与表每 event+user 唯一，状态 CONFIRMED/WAITLISTED/CANCELED/EVENT_CANCELED；报名序号来自锁内递增的 event.next_sequence。满额候补，取消确认在同事务按原序递补仍有效学生。截止后拒绝新报名，递补只在 promotion_until 前进行；再次报名获得新序号。取消活动原子关闭其使用权、参与关系并给所有受影响者通知，不改变其他使用权。

## 提交、权限与恢复

所有写使用有界 `Idempotency-Key`（8–80 个字母、数字、连字符或下划线）。唯一 actor+key；operation 和规范化 DTO 的 SHA256 一并绑定。相同内容返回原收据，异体/异操作 409；只保存已提交成功结果，错误不偷偷保留业务副作用。结果和副作用同事务提交；收据 GET 只可查询本人，断网时以原键恢复。

事务 READ COMMITTED；需要时 event 协调行 → 涉及 floor 按 ID 升序 → 涉及 user 按 ID 升序 → 业务行。获取锁后重新读取 current Clock、空间版本、会话/资格/范围及有效权。logout 与撤权共享 user 行锁，保证排队请求不能用旧入口授权提交。事务内不访问外部网络。临时锁/连接失败 503，客户端最多有限重放同键，不自动换键再造一单。

同事务写 audit 和 notification_outbox。首版通知渠道为持久站内 inbox，分发采用去重事件键，有限批量与独立短事务，可重启恢复。`QUEUED` 只说明待分发，`INBOX` 说明可在站内查询，未读不等于已送达手机。不得伪称微信主动推送已配置。

读取本人记录、老师本人活动和管理员 scope 内请求，不开放别人的预约身份。公开可用查询只返回资源与冲突类型/时间；不泄露占用者。收藏/对比为本人选择的最多 6 项空间，不涉及分配权或黑盒评分。

## API 规划

在现有 `/api/v1` 下追加 availability、favorites、reservations、venue-requests、events、participations、inbox 和 receipts；管理审批/任务目录为 `/admin/...`，组织者为 `/organizer/...`。创建和状态变化 DTO 明确 version/time，不接受任意 status/actor/role 字段赋权。

收据存原响应；当前事实通过详情读回。返回 UTC 带 Z 时间、服务端 now 和阶段投影，不把前端本地时钟当资格。422 保留输入，409 区分空间/个人/版本/幂等冲突，401/403/404/503 使用已有错误封装。

## 必需见证与停止条件

真实 MySQL/HTTP 覆盖：两人同座重叠、同人跨楼层重叠、相邻时段、同键并发/异体、响应丢失后重放、旁人收据拒绝；10 分钟边界与锁等待跨期限；logout/撤权与排队提交；整区批准与子座预约竞争；待审不占位、两个管理员并发批准仅一个；越区/他人申请及活动拒绝；未批准发布、发布容量/版本/窗口；最后名额、取消递补、候补退出、再报名新序、变更保留参与和取消不影响旁人；通知分发重试去重和普通读取不清未知写。

停止条件：任何重复有效权、超容量、越权成功、收据与事务分裂、旧任务释放恢复状态、通知丢失或真实失败被测试绕开。保留首次失败并修复；API/MySQL 阶段证据不自动证明 UI、微信或生产吞吐。
