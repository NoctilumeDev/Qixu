# M8 · 独立测试与产品复核合同 0.1

本阶段在M7有限退出之后执行。两名独立子代理分别担任测试验收者和产品经理，从固定源码、公开合同和原始证据独立恢复判断，不继承施工者自评。报告不是Core裁决，不替代真实数据库、页面或设备观察。

## 固定入口与保护范围

交付时绑定exact source、干净工作树、原Bundle和当前未知账册。阅读M0、领域合同、生命周期/可靠性、M7机制与未知、施工及验迹记录。仅审查期序，不改dome、暗室、青野、验迹或共享环境。数据库/浏览器重型工作串行；只使用带唯一身份且确认归属的夹具，不能按端口猜进程。

## 测试角色

独立追踪身份、版本、冻结、正式发布、有效权、候补、通知、查询、恢复各边界。寻找能击穿已有声明的新失败机制，尤其两项分别合法却组合双权、跨主体迟到、临界截止、回执恢复和当前管理范围。不能复述测试数量或只读绿色报告。可编写忽略目录中的独立反例，重型执行须与主代理协调，不能并行争用qixu_test或owned端口。

每项报告给源码位置、最小前提/操作、实际观察或明确静态推导、影响不变量、优先级、修复或边界建议；未经运行不得称复现。正常拒绝、历史已修、观察器缺证据和产品错误分别处理。

## 产品角色

从学生与老师实际页面检查空间是否可理解、短期/长期入口是否区分、志愿与兜底/候补及结果时限是否可解释、活动预约与场地关系、反馈处理、错误/空/未知/陈旧是否区分、返回和换号是否保持上下文、手机现场操作是否可达。先取实际截图，再判断可用性；原图方向和当前M10未精修边界单列。

产品结构或可用性阻断在M8修；不阻断的视觉精修列入M10。不因前端好看掩盖错误使用权，也不把H5视口称为微信真机。只用显式演示身份和数据；不公开票据或原始私有反馈。

## 反馈处置与退出

保留原报告及首次反例。每项有ACCEPTED_FIX、CORRECT_REFUSAL、ALREADY_REPAIRED、M10_VISUAL、NOT_PROVEN或有依据的REJECTED分类及坐标；已观察核心缺陷不能靠改边界逃避。最小修复单独提交，原标准复验并覆盖受影响邻近链路。

退出要求：两角色均提交有依据报告，阻断发现已修复复验，剩余反馈明确分类；固定候选、原事实及公开投影对齐。新失败只重开相关最小M7项，不抹去首败、不重启无关领域。M8完成不授权宣布生产、多节点、校园SSO、真机或M10视觉已通过。
